# 飞书文档草稿：平台效果评估与内容分发优化报告

## 1. 评估目标

本报告评估平台在内容生成、审核、改写、质量评分、榜单分发和前端性能方面的效果。评估重点是验证系统是否形成从 AI 生成到安全把关、从发布到读者反馈排序的闭环。

## 2. 内容生成效果

创作台输入包括：

- 选题
- 目标受众
- 发布平台
- 内容风格
- Prompt 模板
- 可选素材

AI 输出包括标题、正文、标签、封面引用和发布建议。为了保证演示稳定性，系统实现了双层兜底：

1. 配置 Ark/OpenAI-compatible API 时调用真实模型。
2. 模型不可用或未配置时使用本地 deterministic mock，保证核心流程不断链。

## 3. Prompt 调优过程

Prompt 迭代遵循以下原则：

- 将平台、受众、素材和风险边界写入 Prompt，减少模型泛化输出。
- 要求输出结构化字段，便于前端稳定回填。
- 对容易夸张、导流或违规的表达设置负面约束。
- 对信息流内容强调具体场景、清单化结构和互动问题。
- 对中高风险结果引导进入合规改写流程，而不是直接发布。

平台提供 Prompt 模板管理，创作者可以新增、编辑、删除和选择模板，模板变化会立即影响 AI 生成。

## 4. 审核效果

系统审核覆盖以下风险：

- 涉黄
- 涉赌
- 涉毒
- 敏感信息
- 广告导流
- 低俗内容

审核策略：

- 本地规则保证基础红线稳定命中。
- Ark/OpenAI-compatible AI 审核在配置后提供语义复核。
- 双轨审核取更高风险等级，降低漏判。
- 发布 API 强制要求审核通过 token，审核后修改正文不能复用旧 token。

高危识别目标为 90%+。系统通过 `EvaluationCase` 评估集计算总样本数、高危准确率、误杀和漏判指标。

## 5. 自动干预效果

当内容命中中高风险：

- 高风险内容直接拦截，不能发布。
- 中风险内容要求改写或人工复核。
- 用户可点击“一键合规改写”，系统调用改写 API 替换风险表达。
- 改写后需要重新审核，避免跳过安全闸门。

内容管理页还提供下线、撤回和回滚，支持发布后的治理闭环。

## 6. 质量评分体系

质量分为 0-100，维度包括：

- 原创性
- 结构
- 信息密度
- 表达清晰
- 互动潜力
- 平台适配

评分结果会持久化到 `QualityScore`，在审核页、内容详情页和推荐排序中复用。

## 7. 榜单与分发优化

平台提供三类榜单：

- 热点榜：按真实详情页阅读次数由高到低排序。
- 新发布：按发布时间倒序展示。
- 推荐榜：综合质量、热度、新鲜度、用户反馈和风险惩罚。

推荐公式：

```text
score = quality * 0.45 + heat * 0.30 + freshness * 0.15 + feedback * 0.10 - riskPenalty
```

点赞和评论会更新反馈分，详情页阅读会更新真实阅读数。这样排序不只依赖静态质量分，也会吸收真实消费反馈。

## 8. 性能评估

性能目标：

```text
LCP <= 2500ms
```

自动验证命令：

```bash
npm run test:e2e -- tests/performance/lcp.spec.ts
```

测试流程会先发布一篇轻量内容，再分别测量 `/rankings` 和生成的 `/content/[id]` 详情页。榜单首屏服务端渲染，后续使用 cursor 分页滚动加载。

## 9. 工程验证

常用验证命令：

```bash
npm run test
npm run build
npm run test:e2e -- tests/performance/lcp.spec.ts
```

测试覆盖登录注册、素材、Prompt、草稿、审核、发布、内容治理、榜单、读者反馈和性能。

## 10. 后续优化方向

- 引入更大规模真实审核评估集。
- 将 AI 调用日志、审核命中率和发布失败率接入监控。
- 使用 Redis 缓存榜单和验证码。
- 接入对象存储管理素材图片。
- 当前使用抖音图文沙盒适配层演示一键分发和外部作品 ID 回写；后续在具备开放平台资质后接入抖音/头条真实热点数据或发布 API。
