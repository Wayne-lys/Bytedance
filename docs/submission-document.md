## 项目介绍文档

### 项目简介

本项目是面向短图文创作者的 AI 辅助生产与分发平台，解决创作者从素材准备、AI 生成、合规审核、发布管理到榜单分发和读者反馈优化的全链路效率问题。

### 核心功能介绍

#### AIGC 内容创作

- 支持 Prompt 模板管理：新增、编辑、删除、搜索和选择模板。
- 支持多媒体素材管理：素材上传、合规校验、引用次数、删除和批量管理。
- 创作台支持选题、目标受众、发布平台、内容风格、Prompt 和素材上下文。
- AI 一键生成标题、正文、标签、封面引用和发布建议。
- 支持一键清空、未发布内容保留、发布后自动清空。
- 支持已发布内容二次编辑、重新审核和更新发布。
- 编辑器每 30 秒自动保存草稿，支持 localStorage 本地恢复、云端同步和断网继续编辑。

#### AI 内容安全与质量管控

- 发布前必须审核，审核通过后才允许发布。
- 审核使用本地规则 + Ark/OpenAI-compatible AI 双轨机制；未配置真实 AI 时使用本地规则与 mock 兜底。
- 覆盖涉黄、涉赌、涉毒、敏感信息、广告导流、低俗内容等风险。
- 高风险内容自动拦截，中风险内容要求改写或复核。
- 支持一键生成合规替代内容，改写后必须重新审核。
- 质量评估覆盖原创性、结构、信息密度、表达清晰、互动潜力、平台适配六个维度。
- 内容管理支持下线、撤回和回滚。

#### 内容分发与榜单

- 内容详情页展示发布者、发布时间、封面、多图素材、正文、标签、质量摘要和榜单解释。
- 热点榜按真实详情页阅读次数排序。
- 新发布按发布时间倒序排序。
- 推荐榜综合质量分、阅读热度、发布时间新鲜度、用户反馈和风险惩罚。
- 榜单支持 cursor 分页和滚动加载。
- 读者打开详情页会增加真实阅读次数。
- 点赞和评论会更新反馈分，并参与推荐排序。

### 产品亮点与创新点

- 人机协同闭环：AI 负责生成、审核、改写和质量评分，人类创作者保留确认、编辑、发布和治理权。
- 发布前安全闸门：发布接口校验审核凭证，审核后修改内容不能复用旧审核结果。
- 可解释推荐：榜单详情展示质量、热度、新鲜度、反馈和风险扣分的贡献。
- 真实反馈回流：阅读、点赞和评论不只是展示数据，也会影响推荐排序。
- 演示稳定性：真实 AI 配置可用时调用外部模型，不可用时 mock fallback 保证全链路可演示。
- 工作台式界面：统一侧栏、卡片、状态徽章、审核面板和内容消费页，突出“创作 - 治理 - 分发”的产品氛围。

## 项目技术文档

### 系统架构设计

项目采用单体全栈架构：

- 页面层：Next.js App Router 页面负责工作台、创作台、素材库、内容管理、审核、榜单和详情页。
- API 层：Next.js Route Handlers 提供登录、素材、Prompt、草稿、AI 生成、审核、发布、反馈和榜单接口。
- 领域服务层：`src/features/*` 分离 auth、AI、materials、prompts、drafts、moderation、quality、posts、ranking、evaluation 等模块。
- 数据层：Prisma 统一管理模型、关联关系和持久化。
- AI 层：OpenAI-compatible provider + mock fallback。

核心数据流：

```text
登录 -> 素材/Prompt 准备 -> AI 生成 -> 自动保存草稿 -> 发布前审核和质量评分
-> 审核通过发布 -> 内容详情消费 -> 阅读/点赞/评论反馈 -> 榜单排序
```

### 技术选型与理由

- Next.js：同时承载前端页面和后端 API，适合训练营全栈 MVP 快速交付。
- TypeScript：降低数据模型、API 参数和组件状态出错概率。
- Prisma：数据模型清晰，便于本地 SQLite 和线上 PostgreSQL 切换。
- Tailwind CSS：快速构建一致的工作台界面。
- OpenAI SDK 兼容模式：可以接火山方舟 Ark，也可以接其他 OpenAI-compatible 模型。
- Vitest + Playwright：分别覆盖服务逻辑、组件行为、端到端流程和浏览器性能。

### 核心模块设计

#### AI 内容创作模块

- `src/features/ai/*`：统一生成接口、真实 provider 和 mock provider。
- `src/app/(workspace)/create/creation-studio.tsx`：创作台 UI 和交互。
- 生成结果包含标题、正文、标签、封面建议和发布建议。
- AI 生成中会禁用其他按钮，避免并发操作造成状态错乱。

#### AI 审核模块

- `src/features/moderation/*`：本地规则、AI 审核、review token。
- `/api/moderation/review`：返回风险等级、命中规则、原因和质量分。
- `/api/moderation/rewrite`：生成合规改写内容。
- `/api/posts`：发布前重新校验审核 token，确保先审后发。

#### 榜单分发模块

- `src/features/ranking/ranking-service.ts`：排序公式、热点排序、新发布排序和推荐排序。
- `/api/ranking`：支持 `type=hot|latest|recommended` 和 cursor 分页。
- `src/components/ranking-list.tsx`：榜单 UI 与滚动加载。
- `src/app/content/[id]/page.tsx`：详情页阅读计数、点赞评论和排序解释。

### 数据库设计

核心模型：

- `PostMaterial`：内容与素材关联。
- `ModerationResult`：审核结果。
- `QualityScore`：质量分。
- `RankingMetric`：阅读、点赞、收藏、热度、新鲜度、反馈分。
- `PostComment`：评论。
- `AuditRule`：审核规则。

### 性能优化

- 榜单首屏服务端渲染首批内容。
- 榜单滚动加载使用 cursor pagination。
- 内容详情页图片设置稳定尺寸，降低布局偏移。
- Playwright 真实浏览器测试 `/rankings` 和 `/content/[id]` LCP，目标不超过 2.5 秒。

### 可用性与工程化

- API 使用 Zod 校验参数。
- 高风险发布失败时返回明确原因。
- AI 失败时有 mock fallback。
- 发布、审核、改写、点赞和评论按钮都有 pending 状态，避免重复提交。
- 测试覆盖 API、组件、排序逻辑、内容流程和性能。

## 其他补充材料

### 审核规则与质量评估体系

#### 安全审核规则库

| 风险类型 | 判定边界 | 处置方式 |
| --- | --- | --- |
| 涉黄 | 色情暗示、成人引流、低俗交易 | 高危拦截 |
| 涉赌 | 赌博、下注、稳赚回本、博彩诱导 | 高危拦截 |
| 涉毒 | 毒品、吸毒、违禁药物诱导 | 高危拦截 |
| 敏感信息 | 身份证、银行卡、手机号、住址泄露 | 拦截或改写 |
| 广告导流 | 私信、扫码、进群、外部联系方式 | 改写或驳回 |
| 低俗内容 | 恶俗标题、侮辱、低质夸张表达 | 提示、改写或拦截 |

#### 质量评估体系

质量评分维度：

- 原创性
- 结构
- 信息密度
- 表达清晰
- 互动潜力
- 平台适配

质量分会展示在审核页和详情页，并作为推荐排序的重要因子。

#### 识别 - 干预 - 反馈闭环

```text
风险识别 -> 自动拦截 / 合规改写 -> 重新审核 -> 发布
-> 阅读 / 点赞 / 评论反馈 -> 推荐排序调整
```

## 效果评估与优化报告

### PE（Prompt Engineering）调教过程

- 第一轮：让模型生成短图文，发现输出容易泛化。
- 第二轮：加入平台、受众、素材和风格约束，提升可控性。
- 第三轮：加入风险边界和负面约束，降低导流、夸张和违规表达。
- 第四轮：要求结构化输出标题、正文、标签、封面建议和发布建议，方便前端稳定回填。
- 第五轮：对中高风险内容引导合规改写，而不是绕过审核。

### 审核准确率评估

- 目标：高危问题识别准确率 >= 90%。
- 方法：使用 `EvaluationCase` 种子数据覆盖 safe、medium、high 样本。
- 指标：总样本数、高危准确率、误杀、漏判和风险分布。
- 运行方式：


## 项目自评

- 接入对象存储、Redis、队列和日志监控。
- 在具备资质后接入抖音/头条开放平台，完成真实热点获取和一键分发。
